HOW TO USE: database-parser
====================================

PURPOSE
  Transforms web guide captures, YouTube transcript downloads, user manuals,
  knowledge guides, training docs, and raw PDFs into exhaustively complete,
  senior-engineer-quality LLM reference databases. Strips only true junk
  (navigation chrome, cookie banners, ads, boilerplate) and preserves EVERY
  substantive fact, parameter, code block, table, warning, and procedure step.
  Outputs SQLite FTS5, modular Markdown, Parquet, JSONL, search.py, INDEX.md,
  plus a COVERAGE_AUDIT.md proving nothing relevant was dropped and a
  MANIFEST.md tracing every chunk back to its original source.

CAPABILITIES
  - Auto-detect input types: guide-capture, youtube-capture, scanner, PDF, Markdown, mixed
  - Intelligent junk stripping: removes only nav chrome, cookie banners, ads, boilerplate
  - Conservative by default: when uncertain, KEEPS content and flags for human review
  - Completeness verification: per-source word count comparison with flagged sections
  - Structure normalization: heading hierarchy, code fence repair, table alignment
  - Source provenance tracking: every chunk carries its original URL, path, and capture date
  - Delegates final compilation to the battle-tested dataset-builder engine (build_dataset.py)
  - Generates COVERAGE_AUDIT.md and MANIFEST.md alongside the standard database files
  - Output is fully compatible with ai-database-browser, Producer Pal, and all AI skills

USE CASES
  - "Parse these guide-capture folders into a single searchable database"
  - "Turn these 15 YouTube tutorial captures into an indexed reference database"
  - "Build an LLM reference from these plugin manuals (PDFs) and web guides"
  - "Rebuild the Music Theory database from the updated training docs and captures"
  - "Convert this scanner output (crawled docs site) into a proper reference database"
  - "Parse this mixed folder of PDFs, markdown notes, and web captures into one database"

IDEAS
  - Run guide-capture or youtube-capture first to download source material, then database-parser to compile
  - Use --dry-run to preview what gets stripped before committing to a full build
  - Review COVERAGE_AUDIT.md after every build to verify nothing substantive was dropped
  - Pair with ai-database-browser to immediately search the new database after building
  - Use --detect to quickly survey what source types are in a folder before processing
  - Chain: guide-capture → database-parser → ai-database-browser for end-to-end knowledge pipelines
